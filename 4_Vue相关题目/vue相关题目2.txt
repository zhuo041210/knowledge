1.vuex的响应式处理？
    vuex的内部其实有一个隐藏的vue实例，我们书写的state底层里被赋值给这个vue实例的_data，然后再通过vue本身自带的数据劫持和数据代理实现了响应式
    1.vuex在使用时候实际上使用了vue.use(vuex)插件的形式,这个过程中相当于在每个组件身上都挂载了一个$store，让每个组件都能访问到vuex；
    2.数据在初始渲染的时候，会通过getter收集到所有依赖该数据的地方；
    3.数据发生更新时，vuex内部隐藏的vue实例上的setter监测到了数据变化，调用了数据更新后的对应函数，该函数则是通过getter获取到依赖该数据的所有位置，以实现数据的响应式更新和渲染；

2.vue中遍历的方法有哪些？
    比较常见的for循环我们就不说了
    1.forEach 用于遍历，对每个元素都进行一些操作（比如打印），不会返回新的数组，可以用于修改元素的值
    2.map 用于遍历，对每个元素都进行一些操作（修改值，打印），会返回新的数组，大部分情况下需要接收其返回的新数组，不然如果只是单纯操作数组可以用forEach替代
    3.findIndex 用于遍历，返回第一个满足条件的元素的下标
    4.some 用于检查数组中是否含有至少一个满足所需条件的值 如果是返回true 不是则返回false
    5.every 和some类似 不过是检查是不是所有元素都满足给定的条件 
    6.filter 返回满足条件的所有元素构成的一个数组   find和fileter类似，不过是返回第一个满足条件的元素本身
    7.reduce 累加器，接收两个参数（第一个是接收两个参数的函数，第一个参数代表当前的累加值，第二个参数代表当前的元素；第二个参数是累加值的初始值）
    如arr.reduce((sum,single)=>{
        return sum + single
    },0)可以实现数组的求和

4.如何封装一个组件？
    vue.extend可以用来定义一个组件（用的特别少，因为我们平常都是直接使用export default{xxx}去创建一个实例），vue.extend适用于纯JS去创建一个组件
    vue.component则可以用来全局注册组件，这个其实我们用的也特别少；但实际第三方组件库如elementUI这种，使用了.use方法后会自动遍历所有组件并进行全局注册
    我们实际开发中一般都是从外部导入组件后直接局部注册（比如vue3的setup语法糖和vue2的import后components注册）

5.封装一个可复用的组件时，需要满足哪些条件？
    参考一下elementUI的实现方法：
    1.使用的较多的通用组件，我们可以进行封装；
    2.如果想改变组件内的结构，则使用插槽（默认插槽，剧名插槽，作用域插槽）；
    3.如果想改变组件内的样式，可以使用::deep属性透传；
    4.一些比较通用的属性，比如颜色，大小这些，我们可以专门在组件内设定一个props值，等待父组件使用的时候进行传递；
    5.在组件上封装的自定义事件可以通过组件内的原生事件的回调函数内进行触发，用户的体验即为我触发了原生事件后传递到了外层的自定义事件的触发

6.vue的过滤器怎么使用？
    filter不仅是一个数组函数，vue2中还有一个同名的配置项filter（vue3里好像已经废弃了，官方推荐还是用计算属性）
    全局过滤器 Vue.filter('name',function(val){ return value })  局部注册器 和methods同级的配置项 键为过滤器名 值为过滤器函数
    使用方法即为在模板中的插值语法 {{value | filterName}}即可

7.vue中如何做强制刷新？
    1.location.reload()
    2.this.$router.go(0)
    3.官方推荐的key修改方法：
    因为vue的diff算法里对比的是每个部分的key值，key值一旦更改就表示组件需要销毁重新加载，我们给组件绑定一个key值，在某个时刻的逻辑里修改这个key值，则必定会触发组件的强制刷新，
    而且这种方法完全不影响其它组件，只影响绑定key的组件

8.vue2和vue3的区别是什么？
    区别太大，且涵盖的范围特别多，我们仅举例经典：
    1.响应式原理变化了，vue2使用的是defineProp+数据代理+数据劫持，vue3则是使用Proxy；vue3的优势在于数组的监听不再仅限于数组的方法，对象新增和删除某一属性都能监听，性能损耗更小
    2.代码风格变化了，vue2是选项式API，同一功能的数据方法分散，vue3是组合式API，功能的所有代码聚集在一起，方便阅读与维护
    3.生命周期的名字变化了，vue2的格式是：beforexxx和xxxed vue3变为了onBeforexxx和onxxxed，并且vue3移除了create对应的钩子，变为了setup语法糖
    4.碎片化支持，vue2只允许存在一个根节点，而vue3可以支持多个根节点

9.vue的性能优化如何做？
    1.代码优化：不要把所有数据都放在data中（data里的数据都需要有getter，setter，watcher）,v-for遍历时候使用事件委托（减少绑定事件的性能消耗），
    适当使用keep-alive缓存组件（防止重复的组件销毁加载），循环遍历里的key值唯一性（有利于diff算法），路由懒加载（按需加载），防抖与节流（减小服务器压力）
    2.加载优化：按需加载（异步组件定义，适用于弹窗，类似于路由的懒加载形式，vue3里的defineAsycnComponent，vue2里则是箭头函数写法），路由懒加载，图片懒加载（Vue第三方库，原理是进入视口之后再申请加载）
    3.用户体验：骨架屏（elementUI）
    4.SEO优化：CDN加载第三方模块（cdn即每次请求时不再访问源服务器节点，而是导向最近的cdn节点，访问数据时间大大降低，要求获取数据的地址是cdn格式）
    5.打包优化：tree-shaking（引入的第三方库仅用到部分时，打包工具Vite，Webpack会帮我们删去没有用到的部分，大大减少包体积）
    6.缓存与压缩:客户端服务端缓存，服务端的Gzip

10.首屏优化该如何做？
    1.CDN加速，文件的压缩；
    2.图片懒加载，路由懒加载，异步组件懒加载；
    3.尽量减少dom数量和层级；
    4.服务端渲染SSR：节省了本地渲染的时间，但是对开发的要求和服务器的要求都很高
    （本身我们是浏览器请求到html空壳之后，下载JS然后加载JS，Vue接管DOM，开始渲染页面；
    但是开启SSR之后，不在本地渲染html，而是服务器请求到数据之后自动解析成完整的html结构之后返回给用户，浏览器直接展示（但由于此时很多JS文件未下载，页面只是一个空花瓶，无法交互）
    此时则需要部分JS的下载，然后vue接入管理，浏览器可交互）

11.vue3的性能为什么比vue2好？
    优化的地方很多，我们说重点：diff算法的优化和响应式原理的优化
    1.diff算法的优化，vue3前后虚拟DOM比较起来更加迅速，节点比较变少复用变多，最终渲染变快；
    2.proxy与defineProp的区别：
    proxy直接代理整个对象，是惰性代理，不会在初始化的时候增加getter和setter，真正用到数据的时候才配上getter和setter，如果一个数据永远用不上，那么它不会拥有getter和setter；
    而defineProp是初始化的时候即遍历所有属性，包括深层次的嵌套，给每一个数据立刻加上getter和setter，初次处理耗时；
    同时defineProp为了实现数组的响应式，还对数组的所有方法进行了重写，而proxy对数组的监听是原生支持的，也减少了vue3内响应式的耗时，提升了性能
    3.静态提升：对于完全没有变化的节点，vue3直接复用，而vue2重新渲染；
      静态标记：对于变化的节点，vue3知道其内部具体变化在哪，vue2则需要遍历节点找到变化点；
      事件监听缓存：vue2中每次渲染父组件时，子组件绑定的自定义事件都会视为新的函数，导致子组件虽然无任何变化但仍需要重新渲染；而vue3则使用缓存机制，不需要重新渲染子组件

12.vue3为什么使用proxy？
    1.proxy是惰性监视，直接对数据本身进行代理，不会创建无意义的getter和setter，相对于defineProp提升了性能；
    2.proxy原生支持数组的监视，不需要重新书写数组的方法来实现响应式，也提升了性能；
    3.对于新增和删除的属性proxy也能够响应式监视到，而vue2则需要使用vue.set和vue.delete
    唯一的缺点是，proxy不兼容ie浏览器，而defineProp兼容

15.是否使用过Nuxt.js？
    Nuxt.js和vue.js的关系有点类似于jQuery和JavaScript的关系 是一个基于Vue.js的开箱即用的全栈框架
    可以让用户在SPA和SSR模式之间进行选择 解决了Vue对SSR不友好的问题
    它比vue更加方便 比如组件的自动注册 比如路由的自动添加 且生态环境也很完善 最重要的是可以写后端接口 真正实现前后端一体化的开发
    它可以做前端模拟的真实后端（BFF 服务于前端的后端） 企业开发中的轻量级的后端 但和传统JAVA后端相比稍逊一些 JAVA后端还是主流

16.SEO如何优化？
    vue关注于单页面应用SPA，只要是SPA都不太利于SEO的机制，所以vue只能说是优化SEO，不能说是解决了SEO的问题
    1.SSR服务端渲染，让SEO读取到完整的页面信息
    2.预渲染 prerender-spa-plugin 相当于是一个渲染完毕后的html快照静态资源 和服务端渲染SSR相比轻量，性能损耗低 相当于是一个mini的SSR
    3.多使用语义化标签header nav footer seletion main
