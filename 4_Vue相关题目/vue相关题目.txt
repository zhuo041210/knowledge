1.v-if和v-show的区别？
    v-if和v-show都是用于限制页面上是否展示该元素/组件的条件渲染的工具
    v-if是更加真实的条件渲染，它涉及到真正的销毁，是直接从DOM树上销毁；v-show则是控制display的属性值block和none来实现css层面的是否可见，是渲染树上的销毁，DOM树上仍然保留
    v-if修饰的条件渲染会在不展示的时候适当的解绑事件，如果绑定的是组件标签的话，甚至会触发组件的生命周期钩子
    由于v-if比v-show复杂 其涉及到反复的销毁/重建 但由于其首屏渲染的时候不会考虑不满足条件的元素 所以其初始渲染性能较高 但后续渲染性能较低
    而v-show则是全部都会参与DOM树的构建 所以首屏加载较慢 但是切换时性能消耗则较低

2.如何理解MVVM模型？
    M：Model模型--具体的数据  V：View视图--DOM元素  VM：ViewModel--Vue视图模型
    MVVM则是一种前端开发的一种架构模式，核心是通过VM将M和V关联起来：
    当用户修改页面上的数据时，VM对其进行监测，并自动调整实际的数据；当真实数据被改变的时候，VM对其进行监测，并自动调整页面上依赖此数据的位置，实现了双向绑定

3.v-for中的key值是干什么用的？
    key是每个元素的唯一标识 让vue知道哪些元素被销毁 哪些元素仍保留 哪些元素仅移位 可以减少dom的销毁与重建 提高性能
    当不指定key时 默认index即为key 但这种情况下如果出现表单类型标签（如input）则会存在bug 数据会错位
    key的值一定要稳定且唯一

4.说一说你对vue的生命周期的理解？
    生命周期即为一个组件从创建到销毁过程中比较特殊的一些时刻
    我着重说vue2的，vue3里其实极为类似，只不过名字发生了变化，功能基本是一致的：
    --> 创建钩子（beforeCreated/created）    创建前，什么都没有，数据未初始化，不可更改；创建后，数据初始化完成，监听/计算属性完成，可以更改数据，不会更新视图（因为视图还未挂载）
    --> 挂载钩子（beforeMounted/mounted）    挂载前，数据已全部初始化完毕，虚拟DOM准备完毕，还未挂载组件；挂载后，页面渲染完毕，正常展示（可用于获取异步数据，获取鼠标焦点）
    --> 更新钩子（beforeUpdate/update）      更新前，数据已变化，视图还未变化；更新后，数据和视图都已变化（避免在此阶段进行更新数据操作，防止死循环）
    --> 销毁钩子（beforeDestroy/destroyed）  销毁前，收尾工作（事件解绑，定时器销毁，防止内存泄漏）；销毁后，什么都没有了
    --> 路由组件里的keep-alive和actived/deactived keep-alive保证切换路由时组件不被销毁 actived和deactived则是组件呈现/隐藏时候的生命周期钩子
    vue3里生命周期格式变为：onBeforeCrete/created 然后销毁变为OnBeforeUnmount/unmounted 并且setup替代了初始化的两个钩子
    注意点：对于父子组件，只有子组件完成更新/挂载/销毁后，父组件才能完成更新/挂载/销毁

5.在created和mounted中请求数据有什么区别？
    一般而言在created使用是最好的，也是官方推荐的；但貌似很大一部分人包括我都是习惯性写在mounted里面的
    created时候，数据初始化完成，此时请求异步数据较早，也能正确赋值给初始的数据；
    mounted时候，唯一优势是有些第三方库（echarts）它是需要获取dom元素作为一个图表载体的，此时就必须等dom渲染完毕才能使用；

6.vue中的修饰符知道哪些？
    stop/prevent/capture/self/passive/once/native 分别为 阻止冒泡/阻止默认行为/切换为捕获状态执行/事件目标为自身时触发/立即触发默认行为/只触发一次事件/当前事件当作原生事件
    keyup/keydown/ctrl/alt/meta/left/right/middle 分别为 键盘事件/系统修饰符事件/鼠标事件 都比较语义化
    lazy/trim/number 分别为 表单输入完毕后显示/去除内容前后空格/只接受数字

    比较难理解的三个：
    1.passive: 我们平常滚动鼠标的时候，如果滚动有绑定事件且内部逻辑复杂，则会等待事件执行完毕之后页面才发生滚动（实际生活中很少体验到这个问题），如果加了passive，就是立刻滚动，告诉浏览器我不会preventDefault
    2.lazy：我们通常使用动态绑定v-model 这种情况下只要输入就发生视图的更新 加上lazy后只有enter被触发或者blur事件被触发 才发生更新 减少性能损耗；
    3.native：对于vue2内的组件绑定@click时候，会被识别成自定义事件（组件间通信方式的一种），当我们加上native时，被识别成原生的点击事件，vue3的时候native被废弃了，因为组件也会自动识别为原生事件

7.elementUI是如何做到表单验证的？
    elementUI实现表单验证的三种方法：
    1.写好rule后在表单上绑定:rule='xxx',然后在表单元素上绑定适用的规则props='xxx'
    2.直接内联方式写在表单上的rule中（有点类似与css的内联样式）
    3.自定义规则，写在data/methods中，然后结合方式1进行书写（注意data里则无this，methods里有this）


8.vue如何进行组件通信？
    根据传递信息双方的关系 对组件通信进行分类（仍旧讲的是vue2里的通信方式 vue3其实有很多新增的 后面再看）
    1.父传子：props和ref  ref是给子组件绑定ref后，通过this.$refs.refName.dataName对子组件内部的数据方法进行访问；props则是父组件内以通过动态绑定形式传递参数，子组件内使用props接收即可
    2.子传父：自定义事件$emit 父组件给子组件绑定一个自定义事件（vue2里就算是原生事件 如果被绑定在组件标签上也会被识别为自定义事件）并指定回调 在子组件内部通过$emit触发事件并携带参数 参数会自动传递给父组件的回调函数的参数部分
    3.兄弟间：全局事件总线$bus 类似于自定义事件 只不过是创建了一个特殊的vue实例并把它挂在了vue的原型上（为了让所有组件都能通过this访问，并且该实例身上还需要有$on和$emit方法） 需要传递数据的一方激发事件 需要接受数据的一方绑定事件
    4.vuex： 任意组件的通信 dispatch触发action内存的方法/commit触发mutation内存的方法 state存数据/action执行异步逻辑/mutation修改数据

9.keep-alive是什么？如何使用？
    vue里的一个内置组件 用于缓存路由中未活跃的组件 使其在不显示的时候不被销毁而是存在于缓存中 常用于经常显示/隐藏的组件 用于提高性能/加快页面加载
    使用方法：
    1.把路由的根组件（第一层路由）包裹，则所有路由组件都不会被销毁；
    2.include属性可以配合 单个组件名字 逗号连接的多个组件名字 正则表达式  excluded属性类似于include，但意为不缓存 注意：此时的名字并非路由里的name，而是单个组件的name；
    3.可以在router里面配置meta里的自定义字段isKeepAlive 然后被keep-alive包裹的router-view里写上v-if='$route.meta.isKeepAlive'，同时配合另一个view-router v-if='!$route.meta.isKeepAlive'

    keep-alive拥有max属性，表示最多可以同时缓存到cache内的组件数量，采用的是LRU算法（缓存满时自动淘汰最久没有使用的那个组件），防止页面内存占用过多而越用越卡

10.axios是如何做封装的？
    下载安装 -- 创建实例（create）并传入超时时间和BASE地址（通常配合环境变量env使用，开发生产环境里地址不同）-- 配置请求拦截器（记得返回config）和响应拦截器（http状态码和业务状态码，不同状态码的错误统一处理） -- 正常处理数据，返回成功/失败的Promise实例 -- 
    接口使用时引用绑定好的axios实例，并写上URL,methods,parmas，封装完毕后暴露 -- 组件内引用接口并使用

11.vue路由是怎么实现传参的？
    三种方式：
    1.parmas传参 直接使用this.$router.push({name:'xxx',parmas:{xxx}})即可传参 接收this.$route.parmas.xxx收到即可 有致命缺点：刷新之后参数丢失！！！（但我感觉我实际写业务基本没遇到过这种情况？）
    2.query传参 和parmas传参的方式和接收方式一致 只是换成了query 这种形式的参数会拼接在地址的后方（使用了?和&）
    3.路径传参 在路由中配置占位符 并在请求路径中直接用模板字符串拼接参数即可 注意需要位置相对应

12.vue路由的hash模式和history模式的区别？
    vue默认是hash模式，hash适合做单页面应用
    1.hash模式的路径里带#,history则不带，history更加美观；
    2.hash的兼容性好，更加稳定，适合做后台管理系统；history有利于SEO，适合做C端页面；（顺便扩展下，a端是admin（管理者用的，如整个公司的数据记录），b端是business（企业用的，如管理后台），c端是custom（客户用的，如宣传官网））
    3.hash模式浏览器中刷新正常展示页面，而history模式刷新报错404（必须配合后端）；因为hash不会把#后面的内容发送，而history则会请求完整地址的服务器
    4.hash原理是事件的监听（hashchange），history则是API的调用（pushState/replaceState）

13.路由拦截是怎么实现的？
    使用相对应的路由守卫+路由配置中添加meta里的自定义字段
    比如定义路由的时候，meta内添加一个字段表示是否需要token校验，比如字段名为authorise:true
    然后配合全局的路由守卫：
    beforeEach(to,from,next){
        if(to.meta.authorise){
            if(localStorage.getItem('token') === 'xxx'){
                //模拟对token的校验，如果校验成功则放行
                next()
            }
            else{
                //模拟校验失败，返回某个页面，比如登陆页
                //推荐写法：路由守卫里特有的编程式路由导航next() 可以省去router的跳转，防止再一次触发路由守卫
                next({name:'xxx'})
            }
        }else{
            next()
        }
    }

14.说一说vue的动态路由？
    创建正常的路由并且正常的挂载（所有人可见的路由） 并额外创建一个动态路由（只暴露，不挂载）
    在正常登陆的时候，拿到token后接收该额外创建的路由，并对其进行过滤（也是配合路由里的meta自定义字段）
    过滤好的路由可以作为被遍历的数组绑定给菜单栏进行遍历渲染 出现导航图标
    注意刷新会丢失路由信息 所以一般会配合路由守卫进行检查 每次刷新的时候重新遍历渲染

16.vuex刷新数据会丢失吗？怎么解决？
    vuex在刷新的时候会丢失数据，所有的数据都不再是你操作后的，而是你在vuex内初始设置的一些数据
    一般使用localStorage/sessionStorage存储数据，cookie也行
    监听一下浏览器的刷新事件，在刷新前存储数据；刷新后找storage/vuex要数据即可
    但其实一般数据都是从后端数据库发请求得来的吧

17.computed和watch的区别？
    computed是计算属性，是依赖基础数据或者别的计算属性来得出一个新值，它必须return一个值作为该计算属性的值，计算属性着重在于计算，是一种映射关系，他不是用来处理逻辑业务的 注意，不要直接修改计算属性，而是对计算属性依赖的原始属性进行修改
    watch是监听，是对某个存在的属性（基础属性data，计算属性computed）进行监听，只要值发生了变化（引用数据类型需要手动开启深度监听或者对引用数据类型进行整体赋值）就做一些事，一般用于处理逻辑业务，不需要return
    按道理来讲，所有computed能实现的功能watch都能实现，但是两者语义不同，computed还有缓存，性能较好

18.vuex会在什么场景下使用？
    比较公用的数据进行存储的情况下使用，可以方便的在任意关系的组件间进行数据的传递
    其有三个主要属性：state/actions/mutations/getters 其中state存放数据 getters有点类似于组件内的computed 触发dispatch事件后action处理异步逻辑后使用commit交给mutation mutation对state内的数据进行修改
    可以在state里直接修改数据，但这不被推荐，因为不会被vuex监测到，不方便调试
    vuex也可以通过开启命名空间来进行模块化modules，让每个vuex都只存储相关数据，分类更加紧密
